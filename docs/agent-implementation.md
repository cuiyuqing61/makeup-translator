# 妆译 Agent 实施与验收

网页真实妆教模式使用 `langgraph==1.2.14` 与 `langgraph-checkpoint-sqlite==3.1.1` 编排；产品补全 CLI 继续使用 `qwen-agent==0.0.31`。推理模型由 OpenAI 兼容服务配置。fixture 仍是明确标记的离线演示。原开发环境的上游 LangGraph 参考副本位于 `third_party/langgraph`（提交 `799c2f0`，MIT 许可）；运行时使用固定版本的 pip 包。

当前网页版先执行一次参考图分析、目标拆分和按目标的技法检索。检索只使用参考图的部位、妆效、颜色、质地和强度，每个目标最多保留三张候选卡。分析成功后独立启动步骤编排与产品匹配；各自保存状态、结果、错误和重试记录。一方失败或超时不会撤销另一方。步骤先输出产品类别、用途与形态要求，产品任务直接依据目标和候选技法处理；详情接口在产品到达时按目标、技法和类别关联结果，已保存的步骤文字与步骤图不因此改写。新教程不使用用户化妆时长约束，旧记录仍可读取历史时长字段。

步骤编排使用用户确认或修正后的面部资料、熟练度和工具，保留技法编号、来源、完成标准与相对面部锚点的绘图参数。未确认的面部观察不能写成事实；自然睫毛可见但没有明确睫毛妆效时保持原样。独立审查最多触发两轮返工，失败时分支保持失败状态。步骤图在本地根据固定标准底图、参考图可靠取色与受控蒙版逐步合成；没有可靠颜色时只标出操作范围。最多四张关键步骤图进入局部妆效任务，其余使用现有示意。

产品核验从缓存与本地目录开始，主动“更新来源”跳过快捷结果。后台任务硬上限为 60 秒，约第 52 秒停止新查询；每阶段保存来源与字段快照。到时本地代码生成未确认的部分卡片，不再调用模型。“继续核验”显式开启新任务并复用同一产品版本的快照。已确认产品的刷新候选在用户确认前单独保存，原有产品继续参与教程匹配。

下面保留早期原型的实施和测量记录；涉及单个教程总任务、化妆时长预算与旧步骤图的描述只适用于当时版本。

实测当前 GLM 服务对一次返回整套教程的长结构化请求两次触发读超时，因此规划阶段改成按部位短请求；审查意见能定位部位时只重做对应部位。已完成的目标识别和面部适配可以从缓存复用。文本调用沿用项目既有的低推理强度设置，并限制输出 token 数；这些调整不改变目标、技法与证据校验。

产品选择在实测中对批量步骤两次漏项，因此改为逐步决策：无候选、唯一且证据充分的已有产品或唯一目录候选由本地规则确定；多个合理候选才调用产品 Agent 比较。每个 Agent 决定单独缓存并复核 ID、用途和目录来源。这样不会因为批量 JSON 漏掉一个步骤而重新规划整套教程。

2026-09-29 页面改版后，尚未完成真实用户调试的跟练、局部修改和反馈功能不再作为当前版本功能提供；网页入口及相关公开 API 已移除。下文 2026-09-23 的测试数据保留作原型历史记录，不代表当前版本仍开放这些接口。

## 已实现的模块

| 产品核验 | 品牌别名、商品简称和色号归一化，1011 条有来源的目录记录、102 个品牌、9 个品类，目录优先；最多两路搜索、两页正文；正文/结构化数据读取、字段摘录、社媒权限分离 | 地区、包装版本未知时不补造，不自动确认持有；目录数量不等于独立产品线数量 |

| 效率与记录 | 图片、检索、完整教程、产品结果缓存；产品缓存七天，强制刷新参数；同产品请求进程锁；产品三并发、教程一并发 | 缓存键包含模型/提示词或代码版本/知识/资料/产品快照；已成功的图片分析可在重试中复用。不是任意阶段的通用 DAG 恢复引擎 |

候选图片比对是有界可选工具：最多两个实际来源提供的图片，剩余时间不足八秒则跳过。没有候选图就明确提示，不能声称已经比较。目录命中的身份资料与用户的“确认入库”始终分开。

## 运行与数据

```bash
.venv/bin/pip install -e '.[dev]'
.venv/bin/pytest -q
cd web
npm ci
npm run build
```

Python 3.14 已测试。Qwen-Agent 上游导入需要 `python-dateutil`，本项目显式固定为 `2.9.0.post0`。开发服务启动方式沿用 README。缓存锁使用 macOS/Linux 的 `fcntl`，Windows 需要相应锁适配后再运行。

`.env` 配置 `DASHSCOPE_API_KEY`、`QWEN_AGENT_MODEL`、`QWEN_VISION_MODEL` 与原有 API 地址。`TUTORIAL_TEXT_MODEL` 可单独选择教程规划和复核的文本模型，不影响产品补全 Agent；长结构输出可用 `TUTORIAL_TEXT_MAX_TOKENS` 调整。默认缓存位于 `runtime/agent-cache.sqlite3`，可由 `MAKEUP_CACHE_PATH` 修改。图片仍在本地媒体目录，轨迹不保存图片 Base64、密钥或隐藏推理文本。用量缺失时记为 null，不推算成零费用。
当 `QWEN_BASE_URL` 不是 DashScope 端点时，Qwen-Agent 默认通过 OpenAI 兼容协议的原生 `tool_calls` 调度工具；可用 `QWEN_AGENT_USE_RAW_API=false` 显式切回文本工具协议。

SQLite 仍采用原有 documents 表，新增数据按 kind 隔离，兼容旧资料和教程。首次升级将旧数据库通过 SQLite backup API 备份为 `*.sqlite3.pre-agent-v2.bak` 后标记 schema version 2；原 JSON 保留。恢复时先停止服务，再同时备份当前数据库和媒体目录，使用备份替换数据库。不要在服务运行时直接覆盖 WAL 数据库。

## 新增接口

- `POST /api/tasks/{id}/reply`：`{"answer":"包装上的系列名"}`。
- `POST /api/products/{id}/enrich?force_refresh=true`：跳过结果缓存与目录快速返回，重新核验。

除已下线的跟练与反馈接口外，其余旧接口保持兼容。编辑产品或删除任务会取消旧任务；用户选择候选仍需要证据核验和确认步骤。历史教程通过生成时的产品、用户资料、技法快照解释结果，删除现有产品不改写旧教程。

3. 可选候选图比对的真实两图样本、复杂工具替代的人工效果验证：未完成；没有来源图或不支持的替代会明确拒绝/跳过。
4. 通用的阶段 DAG 恢复、跨步骤复杂重规划、细粒度功能属性（如粉底/散粉）匹配：本次保留为后续扩展；现版本不承诺支持所有修改。重启后未完成外部请求的最终计费状态仍未知。

## PPT 建议（六页）

1. 场景：输入参考妆 + 已有产品 + 长期资料，输出可执行的步骤。
2. 架构：一个 Qwen-Agent 核心 + 两组工具 + 代码预算/证据/约束层 + SQLite。
3. 产品闭环：官方目录与公开搜索、字段原文、歧义澄清、用户确认。
4. 教程闭环：多模态观察、技法检索、产品用途、硬约束和逐步图示。
5. 成本：真实样本的阶段耗时与模型调用，目录缓存 1→0 次；不展示未测的总体提速比例。价格未配置时只展示 token 用量，不虚构人民币成本。
6. 已实现 / 已验证 / 待人工验证：展示真实日志和演示录屏，说明为控制时间与 API 费用采用单 Agent、结构化检索和局部确定性修改；向量库、多 Agent 辩论、视频跟练和虚拟试妆留作后续。
